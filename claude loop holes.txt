PART 2: HIGH AUDIO QUALITY (HONEST VERSION)
================================================================================

2.1  Fix the incorrect claims
- Remove or correct "384 kbps studio bitrate". Raw s16le stereo PCM at 48 kHz

  bitrate changes.

  complexity high if CPU allows (lower it automatically on a weak host).
- Be honest in the spec: YouTube audio is already lossy (Opus ~130-160 kbps
  or AAC), so the pipeline preserves quality but cannot improve it.

2.2  Two playback paths
- Path A (no filter, volume 100): send the YouTube Opus stream directly with
  no decoding and re-encoding wherever the library supports it, so there is no
  extra quality loss.
- Path B (filter active or volume not 100): decode with ffmpeg, apply the
  filter chain, then encode to Opus.

  filter or volume.
- Choose the best available audio format in yt-dlp (prefer bestaudio with
  opus/webm, fall back to m4a).

2.3  Resampling
- YouTube Opus is already 48 kHz, so only resample when the source is not
  48 kHz. Keep the high-quality resampler setting (for example
  aresample=48000:precision=28) only in the path where resampling is needed.
  Remove the "28-bit Chebyshev" claim unless I verify it against the real
  ffmpeg options.

2.4  Volume without clipping
- Use a gain stage plus a limiter in the ffmpeg chain (for example volume and
  alimiter) so volumes above 100 and Bass Boost do not clip.

- Build each filter as a proper ffmpeg filter chain.

- Nightcore and Vaporwave change speed: keep the progress bar and lyrics sync
  correct by applying the speed factor to the elapsed time.
- Make 8D Audio lightweight (apulsator or a cheap alternative) so it does not
  stutter on a small CPU. Add a note on which filters are CPU heavy.

2.6  Buffering
- Keep a small read-ahead buffer (the 64 KB buffer is fine) but make it
  configurable. If the stream stalls, rebuffer and resume instead of
  skipping the song.
- Pre-resolve the next track in the queue (get the stream URL ahead of time)
  so there is no gap between songs.
